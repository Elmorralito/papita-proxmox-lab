setup-pve-node.sh — reference manual
=====================================

What it is
  Guided, interactive setup for a Proxmox VE node: APT/repos, power and network
  helpers, sensors/NTP/hosts, Tailscale, boot/shutdown hooks, notifications,
  SMART monitoring, firewall, backups, and UI tweaks.
  Run as root on the node. Prompts are validated (y/n, y/c/n, y/?/n, cron lines,
  WoL-capable interfaces, etc.) via deploy/utils.sh.

How to run
  Local (repository checkout; deploy/utils.sh, deploy/usage.sh, src/python/, and this file):
    bash src/bash/setup-pve-node.sh
    bash src/bash/setup-pve-node.sh --help    # this manual in a pager, then exit
    Step 7 resolves src/python/ via ../python (misc/cluster + data).

  Remote (deploy/proxmox.sh copies src/bash/ → <target-path>/deploy/, src/python/ →
  .../deploy/python/, plus utils.sh, usage.sh, and deploy/data/setup-pve-node.usage.txt,
  then runs setup-pve-node.sh over SSH):
    ./deploy/proxmox.sh -ip <host> ...

First prompt (after the on-screen step list)
  y              Start from step 1 (full run)
  n              Exit immediately; no further steps
  1-17           Skip all steps before this number; begin at that step
  (empty)        Same as starting from the beginning (step 1)
  h, help, ?, usage, -h, --help
                 Show this manual again in the pager, then ask again (CLI --help as above)

Failure behavior
  Step 1 (APT) can exit the whole script on error (missing apt-dependencies.list,
  failed apt install, or jq / vim / unattended-upgrades missing after install).
  Steps 2-17: errors are usually logged and the script continues with the next step.

--- Step 1 — APT configuration ---
  Gate: answer "n" at 1. QUESTION to skip the entire step.
  Repositories: Debian bookworm base + PVE trixie .sources (no-subscription, enterprise, ceph-squid).
  Then: apt update && dist-upgrade && autoremove && clean.
  Dependencies from apt-dependencies.list (1.1 confirm before install).
  Enables unattended-upgrades; upgrade cron (default 0 4 * * 6).
  Optional 1.3: install intel-microcode or amd64-microcode based on CPU vendor.

--- Step 2 — Hibernate / sleep off ---
  vm.swappiness=0; systemd sleep.conf + logind drop-ins; unmask sleep targets if needed.

--- Step 3 — Wake-on-LAN ---
  ethtool wol pg, wol.service, pvenode config set --wakeonlan <mac>.

--- Step 4 — Locales ---
  locale-gen + update-locale (defaults en_US.UTF-8).

--- Step 5 — lm-sensors ---
  sensors-detect --auto; enable lm-sensors.service. Supports deploy/proxmox.sh get-temp.

--- Step 6 — Time sync (chrony) ---
  Gate: "n" skips. 6.1: NTP servers (space-separated; empty = pool.ntp.org).
  Writes /etc/chrony/chrony.conf.d/99-papita-ntp.conf and restarts chrony.

--- Step 7 — Cluster /etc/hosts (pre-cluster) ---
  Run before pvecm create/join so nodes resolve each other by name.
  7.1: DNS domain suffix (required). Literal (cluster.home.arpa) or keyword (oldtimers.*,
  *.oldtimers.lan). Trailing .* tries zone labels from python/data/default.domain.suffixes.list.
  7.2: FQDN regex (empty = python/data/default.hosts.regex).
  Resolves candidates from python/data/default.hosts.list via python/misc/cluster/discover_hosts.py
  (Python 3 + DNS). Includes this host when resolvable. 7.3: confirm merge into /etc/hosts
  between markers # BEGIN/END papita-pve-cluster-hosts.

--- Step 8 — Tailscale (install + forwarding + firewall + optional NAT) ---
  y/c/n install flow; sysctl forwarding; 8.1 cluster.fw Tailscale ACCEPT rule; 8.2 optional NAT masq.
  All cluster nodes install Tailscale (AWS EFS data plane). Remote admin uses main node only.

--- Step 9 — tailscale up ---
  Hostname, tags; tailscale up --accept-dns --ssh --reset.
  9.0: main vs worker — workers skip --advertise-routes (pfSense advertises 172.16.0.0/16).
  Main node: route advertisement usually unnecessary; optional fallback in default.lan.routes.list.
  Optional 9.4: post-init sanity (status, IPv4, MagicDNS, admin-console reminders).

--- Tailscale topology (this lab) ---
  Hybrid model:
  - Every PVE node: steps 8–9 (Tailscale client for EFS over tailnet).
  - Main node only: step 10.2 (/etc/default/pve-main-node), step 17 (Tailscale TLS :8006).
  - Worker nodes: no subnet routes, no step 17.
  - pfSense (172.16.0.1): subnet router for 172.16.0.0/16 — remote admin reaches LAN via pfSense.
  - deploy/tailscale-pfsense-lan.sh configure — approve route + patch ACLs from workstation.
  - deploy/proxmox.sh --ip-address 172.16.0.101 — cluster ops via main node LAN IP.

--- Step 10 — Post-startup ---
  Ceph osd unset noout after boot; optional quorum wait (10.3, /etc/default/papita-post-startup);
  main-node WoL peers (10.2 → /etc/default/pve-main-node).

--- Step 11 — Pre-shutdown ---
  Optional pvesh stopall (11.2–11.3 → /etc/default/papita-pre-shutdown); Ceph osd set noout.

--- Step 12 — Email notifications ---
  postfix (optional SMTP relay 12.3); pvesh set /cluster/options --mailto / --mailfrom.

--- Step 13 — SMART monitoring ---
  smartmontools + /usr/local/sbin/papita-smart-scan.sh cron (13.1 schedule; default 0 3 1 * *).

--- Step 14 — Enable Proxmox cluster firewall ---
  Sets enable: 1 in /etc/pve/firewall/cluster.fw after Tailscale rule exists (step 8.1).

--- Step 15 — PVE subscription nag (web UI) ---
  proxmoxlib.js patch + pveproxy restart.

--- Step 16 — Periodic backup (vzdump) ---
  16.1 storage (default local), 16.2 mode (default snapshot), 16.3 compress (default zstd),
  16.4 cron schedule (default 0 2 * * 0). Installs /usr/local/sbin/papita-vzdump-all.sh.

--- Step 17 — Proxmox Web UI TLS via Tailscale ---
  Main node only. tailscale cert + pvenode cert set; optional renewal cron (17.2).
