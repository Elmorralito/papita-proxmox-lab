tailscale-pfsense-lan.sh — reference manual
============================================

What it is
  Automates Tailscale admin API work to expose a pfSense LAN subnet over the
  tailnet: approve subnet routes on the pfSense device, merge ACL grants for lab
  tags, and verify connectivity. Complements manual pfSense WebGUI steps
  (advertised routes, NAT, firewall). Run from your workstation with network
  access to the Tailscale API.

  Topology: all PVE nodes join Tailscale for AWS EFS; pfSense advertises
  172.16.0.0/16; remote Proxmox admin uses main node (172.16.0.101) only.

How to run
  From the repository root (requires deploy/utils.sh and deploy/usage.sh):
    ./deploy/tailscale-pfsense-lan.sh ACTION [OPTIONS]

  Load secrets from a file (recommended):
    cp .env.example .env    # edit TAILSCALE_API_KEY, then:
    ./deploy/tailscale-pfsense-lan.sh --env-file .env configure

  Show this manual:
    ./deploy/tailscale-pfsense-lan.sh --help
    ./deploy/tailscale-pfsense-lan.sh help

ACTION (required, position 1)
  configure       Full workflow: find pfSense device → approve subnet route →
                  patch ACL grants → wait 5s → verify connectivity (default).
  approve-routes  Enable LAN_CIDR on the pfSense Tailscale device (route must
                  already be advertised on pfSense). Does not change ACLs.
  patch-acl       Merge grants and autoApprovers.routes into the tailnet ACL
                  JSON via API. Idempotent (skips duplicate grant tuples).
  verify          Local checks only (no API): route lookup, tailscale ping, ICMP
                  ping to LAN_TEST_IP, HTTPS :8006 probe. Safe without API key.
  pfsense-steps   Print pfSense WebGUI checklist (no API). Run before configure
                  if routes are not advertised yet.

Options (before ACTION)
  --env-file, -ef PATH   Source shell variables from PATH (e.g. .env). Parsed
                         before utils.sh/usage.sh are loaded.

Environment (API actions: configure, approve-routes, patch-acl)
  TAILSCALE_API_KEY      Tailscale API key (tskey-api-...). Required for API
                         actions. Create at https://login.tailscale.com/admin/settings/keys
  TAILSCALE_TAILNET      Tailnet DNS name (default: tailf1ad0d.ts.net)

Optional overrides (environment variables)
  LAN_CIDR               Subnet behind pfSense (default: 172.16.0.0/16)
  LAN_TEST_IP            Main PVE LAN IP for verify (default: 172.16.0.101)
  MAIN_PVE_LAN_IP        Main node LAN IP for admin ACL grants (default: 172.16.0.101)
  MAIN_PVE_TAILSCALE_NAME  Optional MagicDNS name for direct tailnet UI verify
  PFSENSE_NAME           Substring match for pfSense device name/hostname in
                         admin device list (default: pfsense-fw001)

Prerequisites
  curl, python3          Required for Tailscale API calls and ACL JSON merge.
  tailscale CLI          Optional; used by verify for tailscale ping.
  pfSense                Must advertise LAN_CIDR before approve-routes/configure
                         succeed (see pfsense-steps).

--- Action: configure ---
  1. Validates TAILSCALE_API_KEY, TAILSCALE_TAILNET, curl, python3.
  2. GET /tailnet/{tailnet}/devices — finds device where PFSENSE_NAME matches
     name or hostname (case-insensitive).
  3. approve_subnet_route: GET device routes; if LAN_CIDR not in advertisedRoutes,
     warns and exits non-zero with pfSense instructions; else POST enabled routes.
  4. patch_acl_grants: GET current ACL; merge tagOwners, grants, and
     autoApprovers.routes (see below); POST full ACL document.
  5. sleep 5, then verify_connectivity.

--- Action: approve-routes ---
  Same device lookup and route approval as configure; no ACL patch, no verify.

--- Action: patch-acl ---
  Merged grants (src → dst, ip) — only appended if not already present.
  Replaces superseded tag:server-node → whole LAN :8006 grant with main-only rule.

    tag:auth-client              → LAN_CIDR                    *
    tag:pfsense-oldtimers-client → LAN_CIDR                    *
    tag:private-node             → LAN_CIDR                    *
    tag:private-node             → MAIN_PVE_LAN_IP/32          tcp:8006, tcp:22
    tag:pve-oldtimers-cluster    → LAN_CIDR                    *
    tag:server-node              → MAIN_PVE_LAN_IP/32          tcp:443, tcp:8006, tcp:22
    LAN_CIDR                     → tag:pve-oldtimers-cluster   *
    LAN_CIDR                     → tag:private-node            *
    tag:private-node             → MAIN_PVE_TAILSCALE_NAME     tcp:8006, tcp:22  (if set)

  tagOwners ensured for: tag:auth-client, tag:pfsense-oldtimers-client,
  tag:pfsense-lan-router, tag:private-node, tag:pve-oldtimers-cluster,
  tag:server-node (each default owner: autogroup:admin if missing).

  autoApprovers.routes: LAN_CIDR appended for tag:pfsense-lan-router only
  (PVE workers do not advertise routes; avoid dual routers).

--- Action: verify ---
  route -n get LAN_TEST_IP (best effort)
  tailscale ping -c 2 LAN_TEST_IP (if tailscale in PATH)
  ping -c 2 -W 3 LAN_TEST_IP (ICMP may fail if host blocks ping)
  curl -fsSk https://LAN_TEST_IP:8006/ (Proxmox UI via pfSense subnet route)
  curl -fsSk https://MAIN_PVE_TAILSCALE_NAME:8006/ (if MAIN_PVE_TAILSCALE_NAME set)

--- Action: pfsense-steps ---
  pfSense WebGUI (LAN 172.16.0.0/16; gateway 172.16.0.1):

  1. VPN → Tailscale → Settings → Routing
     - Advertised Routes: LAN_CIDR (172.16.0.0/16)
     - Accept Subnet Routes: enabled (site-to-site)
     - Save; approve in Tailscale admin

  2. Firewall → NAT → Outbound → Hybrid outbound NAT
     - Add: Interface Tailscale, Source LAN_CIDR, Destination any,
       Translation interface address

  3. Firewall → Rules → Tailscale (top → bottom; keep all three passes)
     - Pass AUTH_CLIENTS → This firewall  TCP 22,443  (merge old :443/:80/:22 rules; drop 80 if unused)
     - Pass AUTH_CLIENTS → 172.16.0.1/32  TCP 22,443  (pfSense LAN IP — WebGUI, pfREST via subnet route)
     - Pass AUTH_CLIENTS → LAN_CIDR (172.16.0.0/16)  *  (tailnet → lab LAN; required — do not block)
     - Optional: Block any → any below the passes

  4. Skip LAN net → 100.64.0.0/10 unless a LAN-only host must reach tailnet via pfSense
     (PVE nodes use their own Tailscale client in this lab)

  5. Optional — restrict Proxmox UI to main node:
     - Alias TAILNET_ALLOWED = admin 100.x /32 addresses
     - Pass TAILNET_ALLOWED → MAIN_PVE_LAN_IP TCP 8006, 22
     - Block 100.64.0.0/10 → worker PVE LAN IPs TCP 8006

  (Former step 5 Tailscale 100.64.0.0/10 → LAN_CIDR is superseded by AUTH_CLIENTS rules above.)

  Then run: ./deploy/tailscale-pfsense-lan.sh configure

Failure behavior
  Missing API key, tailnet, curl, or python3: ERROR log and exit 1.
  pfSense device not found: ERROR and exit 1.
  Route not advertised on pfSense: WARN with WebGUI hint; exit 1 (approve-routes
  / configure).
  Tailscale API HTTP non-2xx: ERROR with response body; exit 1.
  Unknown ACTION: ERROR then this manual; exit 1.
  Empty ACTION or --help: show this manual; exit 0.

Examples
  export TAILSCALE_API_KEY='tskey-api-...'
  export TAILSCALE_TAILNET='tailf1ad0d.ts.net'
  ./deploy/tailscale-pfsense-lan.sh configure

  MAIN_PVE_TAILSCALE_NAME=pvenode-001.tailf1ad0d.ts.net \
    ./deploy/tailscale-pfsense-lan.sh --env-file .env verify

  ./deploy/tailscale-pfsense-lan.sh pfsense-steps
